A small language that compiles to C.

Larimar transpiles to a single C99 file, has no garbage collector (memory is freed in blocks, at points you can see in the code), and its compiler is written in Larimar itself.

Status: 97 tests on Linux and macOS: memory, threads, network and debugger.

The language

What the language brings

The ideas the design rests on, implemented and tested.

Checks at compile time and at run time

Types are required and there are no uninitialized variables. Integers that overflow wrap around, with no undefined behavior. An index out of range or a division by zero stops the program with a message instead of corrupting memory.

No garbage collector

Memories are freed in whole blocks, at visible points in the code. A lifetime rule, checked at compile time, keeps anything from pointing to memory that was already freed.

Threads checked at compile time

The compiler rejects sharing mutable state between threads. Only values and objects of synchronized classes cross over, with one lock per object.

UTF-8 text

Immutable UTF-8 String, interpolation, views without copies, text blocks and raw text. StringBuilder to build long texts without extra copying.

Patterns and enums

switch with patterns over enums, classes and Any, guards with when, and the is operator to tell types apart in one line.

Modules and projects

Each file is a module with its own namespace. Projects with larimar.toml, built into a single executable that can link C libraries.

Patterns and enums

A switch over an enum covers every case

A switch over an enum must cover all of its variants (or have a default). If you add one tomorrow, the compiler points at every switch to revisit. Cases do not fall through, and fields are taken out by name.

  • Several values in one case: case 1, 2, 3 -> ...
  • Guards: case Circle { radius } when radius > 10.0 -> ...
  • Type pattern: case Dog d -> ...
  • In a condition: if (pet is Dog d) { ... }
patterns.lar
enum Shape {
    Circle(radius: float64),
    Rect(width: float64, height: float64),
    Empty
}

function area(s: Shape): float64 {
    return switch (s) {
        case Circle { radius } -> 3.0 * radius * radius;
        case Rect { width: w, height: h } -> w * h;
        case Empty -> 0.0;
    };
}
src/geo/shapes.lar
// src/geo/shapes.lar

Modules

Each file is a module

What you declare is private unless you mark it public. You import with a prefix, with an alias, or just the names you need. Modules may import each other in a cycle, and in the generated C each name carries its module: geo__shapes__area.

// Three ways to import
import geo.shapes; // shapes.area(s)
import geo.shapes as g; // g.area(s)
import geo.shapes { Shape, area }; // area(s)
Memory

Memory without a collector

Larimar has no GC and no free(). Everything that is made lives in a memory (an arena), and each memory has an owner you can see in the code: a statement, a block, an object. When the owner ends, its memory is freed whole, at once. That is why no memory is left behind.

Arenas

The ; and the } free memory

A memory asks the system for big blocks and hands out pieces of them; nothing is freed on its own. The compiler picks each thing's memory by how long it must live, without you writing anything:

  • What is not stored anywhere (arguments, parts of an expression, the text of a println) lives in the statement's memory, freed at the ;.
  • A variable's data lives in its block's memory, freed at the }. In a loop, on every turn.
  • A program that runs for a long time (a server, a loop over files) does not pile up: what each turn makes is freed every turn.
  • It is freed by any exit from the block: at the end, with return, break, continue, or when an error leaves.
loop.lar
function greet(name: String): void {
    // the upper-case text: freed at the ;
    println("hello ${name.toUpperCase()}");
}

function main(): int32 {
    for (i in 0..3) {
        // in this turn's memory
        let label: String = "item ${i}";
        greet(label);
    }   // freed at the }, every turn
    return 0;
}
loop.c

    printf("hello %.*s\n", (int)t_12.len, t_12.ptr);
    rt_mem_free(&tmp_11);             /* the ; */
}

for (int32_t i = from_13; i < to_14; i++) {
    RtMem mem_0 = rt_mem_growable();
    ...
    greet(label);
    rt_mem_free(&mem_0);              /* the } */
}

The C the compiler writes, trimmed: one memory per statement and one per turn, each with its release.

clone()

An arena of your own, and clone() for what stays

When a task makes a lot and you only need part of it, you give it its own memory: byte[*] in heap. Everything the task makes goes there, and it is freed together when the block ends.

  • The rows, the list and the joined text live in scratch, and are freed together when fill returns.
  • Only the summary survives: clone() copies it into r's memory.
  • The lifetime rule: a value cannot be stored somewhere that lives longer than the memory it was made in. Without clone(), the program does not compile, instead of leaving r pointing to freed memory.
report.lar
class Report {
    let summary: String = "";
}

function fill(r: Report, rows: int32): void {
    let scratch: byte[*] = [] in heap;  // an arena
    let lines: String[*] = [] in scratch;
    for (i in 0..rows) {
        lines.push("row ${i}");         // in scratch
    }
    let text: String = lines.join(", ") in scratch;
    r.summary = text.clone();      // only this stays
}                                     // scratch: freed whole

What the compiler says if the clone() is removed:

Semantic Error [report.lar:12]: This value lives in memory 'scratch', but field 'summary' lives longer (in 'r' (owned by the caller)). Use .clone() to copy it there.

What a function returns

It is made directly in the caller's memory, without copies: let puts it in its block, push in the list, a field in its object.

The default memory

in default lives for the whole program: configuration, caches, global data. Nothing ends up there without it showing in the code.

Memory on the stack

byte[4096] is a fixed-size memory on the stack, with nothing asked from the system. If it fills up, the program stops with a message.

Concurrency

Threads checked at compile time

A Thread is an object that lives in a memory, and its run is a lambda. When the thread's memory is freed, the program waits for it to finish: it never outlives its memory.

synchronized class

Protects its data with a lock. Each method takes it on entry and releases it on exit: two threads are never inside the same object at once.

What the compiler rejects

A thread that changes a global variable, touches a plain object, or uses a shared memory other than the default one: a compile error.

threads.lar
synchronized class Counter {
    let total: int64 = 0;
    function add(n: int64): void { self.total += n; }
    function get(): int64 { return self.total; }
}

function main(): int32 {
    let shared: byte[*] = [] in heap;
    let counter: Counter = {} in shared;
    {
        let workers: byte[*] = [] in heap;
        for (w in 0..4) {
            let t: Thread = {
                run: () -> {
                    for (k in 0..1000) { counter.add(k as int64); }
                }
            } in workers;
            t.start();
        }
    }
    println("${counter.get()}");
    return 0;
}

4 threads × 1000 additions. Output: 1998000

queue.lar
synchronized class Queue {
    let items: int32[8] = [];
    let closed: bool = false;

    function put(v: int32): void
            wait until (self.items.length < 8) {
        self.items.push(v);
    }

    function close(): void { self.closed = true; }

    function take(): int32
            wait until (self.items.length > 0 || self.closed) {
        if (self.items.length == 0) { return -1; }  // closed
        let v: int32 = self.items[0];
        let rest: int32[8] = [];
        for (i in 1..self.items.length) {
            rest.push(self.items[i]);
        }
        self.items = rest;
        return v;
    }
}
wait until

Waiting for something to happen

A method of a synchronized class can say in its signature when it may run. Whoever calls it waits there, without using the processor, until the condition holds.

  • put waits for room; take, for an item or for the queue to be closed.
  • Nobody notifies by hand: when any method of the object ends, the waiting threads look at their condition again.
  • The body starts with the condition true and the lock held.
in main
let queue: Queue = {};
let consumer: Thread = {
    run: () -> {
        let sum: int64 = 0;
        while (true) {
            let v: int32 = queue.take();
            if (v < 0) { break; }
            sum += v as int64;
        }
        println("sum ${sum}");
    }
};
consumer.start();
for (i in 1..101) { queue.put(i); }
queue.close();
consumer.join();

main produces 100 numbers and the thread adds them up, through a queue of 8. Output: sum 5050

thread safe

Functions that several threads call

Whoever designs an API marks with thread safe the function its threads will call at the same time. Whoever uses it writes a plain lambda, and the compiler checks it like the run of a Thread.

  • Using stats is fine: it is synchronized. Using a plain list inside onConnect does not compile.
  • std.net brings TcpServer, UdpServer and TlsServer (https with OpenSSL), written in Larimar on top of this rule.
  • Each connection is served with its own memory, freed when it ends.
server.lar
// in std.net
public class TcpServer {
    ...
    let onConnect: (TcpSocket) -> void thread safe;
}

synchronized class Stats {
    let served: int32 = 0;
    function add(): int32 { self.served += 1; return self.served; }
}

let stats: Stats = {};
let server: TcpServer = {
    port: 8080,
    threads: 8,
    onConnect: (client: TcpSocket) -> {
        client.writeText("hello #${stats.add()}\n");
    }
};
server.run();

8 threads serve at the same time, without races: the compiler checked it.

Interoperability

Calling C

The functions, constants, globals, structs, pointers and resources of a C library are declared, not wrapped. And with export function, C can call Larimar too.

interop.lar
c_include "<stdio.h>";
c_include "<math.h>";

extern function printf(format: String, ...): int32;
extern function sqrt(x: float64): float64;

function main(): int32 {
    printf("sqrt(2) = %f\n", sqrt(2.0));
    return 0;
}
c_include
Adds a C #include.
extern function
Declares a C function.
extern type
An opaque pointer, a C type or a C struct.
export function
Makes a function callable from C.
released by
A C resource (FILE*, a socket) is released with its memory.
#when windows
What each system needs, chosen at compile time; every branch is checked.

Any for free-form data

For data whose shape you do not know in advance (configuration, JSON, messages) there is Any: a value that can be a number, bool, String, null, object, struct, enum or table.

any.lar
function main(): int32 {
    let config: Any = {
        "web", "api",
        name: "server",
        port: 8080,
    };
    let port: int32 = config.port as int32 ?? 80;
    println("${config.name} on ${port}");
    return 0;
}
By design

What Larimar does not have

Decisions, not a to-do list: each one with what you use instead.

No generics

Arrays (T[N], T[*]) and Any already hold any type, and interfaces cover the rest.

No garbage collector

Memory is freed at the ; and at the }: you always see where.

No constructors

A literal creates the object; when something must be validated, a plain function does it.

No overloading

Each name is one function, and the generated C reads without guessing.

No hidden jumps

An error is a value that is returned, and throws announces it in the signature.

No hidden threads or async

Threads are created in plain sight, and the compiler checks what they share.

No surprise null

Only what carries ? can be null.

No implicit conversions

Numeric types are converted with as, in plain sight: int32 + int64 does not compile.

No undefined behavior

Integers wrap around, indexes are checked, and a failure stops with its file and line.

Tools

What comes with the compiler

All written in Larimar, like the compiler.

Language server

Errors as you type, hover, go to definition, references, completion and signature help.

Debugger

larimar dap sits between the editor and lldb-dap: the stack with Larimar names, its variables, and panics as exceptions.

Readable C and AddressSanitizer

The generated C compiles with no warnings under -Wall -Wextra -pedantic, and the runtime teaches AddressSanitizer to see inside memories.

Standard library

Files, console, streams, paths, JSON, regular expressions, TCP and UDP with their servers, a TLS server, and an HTTP and HTTPS client. Almost all written in Larimar.

VS Code extension

Highlighting, live errors and debugging with breakpoints, on top of larimar lsp and larimar dap.

Linux, macOS and Windows

Meant for all three; what differs between them is written with #when. For now, the tests run mostly on Linux.

Errors with throws

Expected errors are enums: the signature says what each function may throw, and the compiler makes you catch it with try / catch or declare it.

errors.lar
enum FileError {
    NotFound,
    Denied(user: String)
}

function open(path: String): int32 throws FileError {
    if (path == "") { throw FileError.NotFound; }
    return path.length;
}

function main(): int32 {
    try {
        println("read ${open("data")}");
    } catch (FileError e) {
        switch (e) {
            case NotFound -> println("not found");
            case Denied { user } -> println("denied to ${user}");
        }
    }
    return 0;
}

The project file

A larimar.toml describes the project and how to build the generated C. An unknown key is an error, so a typo does not go unnoticed.

  • sources: your own .c files, built with the program
  • libraries: libraries to link (-l)
  • library_paths: where to look for them (-L)
  • include_paths: header folders (-I)
  • flags: options for the C compiler
larimar.toml
[project]
name = "hello"
version = "0.1.0"
main = "src/main.lar"
output = "dist/hello"

[c]
compiler = "gcc"
flags = ["-O2", "-Wall"]
sources = ["csrc/helpers.c"]
libraries = ["m"]
